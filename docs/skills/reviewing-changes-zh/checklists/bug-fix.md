# 错误修复审查检查清单

## 多次通过策略

### 第一次通过：理解错误

<thinking>
在评估修复之前：
1. 原始错误/损坏行为是什么？
2. 期望的正确行为是什么？
3. 根本原因是什么？
4. 如何发现此错误？（用户报告、测试、生产）
5. 严重性是什么？（崩溃、数据丢失、UI 故障、小烦恼）
</thinking>

**1. 了解根本原因：**
- 损坏的行为是什么？
- 是什么导致的？
- 此修复如何解决根本原因？

**2. 评估范围：**
- 更改了多少文件？
- 这是有针对性的修复还是更广泛的重构？
- 这是否影响多个功能？

**3. 检查副作用：**
- 这可能会破坏其他功能吗？
- 是否有未考虑的边缘情况？

### 第二次通过：验证修复

<thinking>
系统性评估修复：
1. 此修复是否解决了根本原因或只是症状？
2. 是否有未覆盖的边缘情况？
3. 这是否会破坏其他功能？
4. 修复是本地化的还是在代码库中产生连锁反应？
5. 我们如何防止此错误返回？
</thinking>

**4. 代码更改：**
- 修复是否有意义？
- 这是最简单的解决方案吗？
- 包含了不必要的更改吗？

**5. 测试：**
- 有回归测试吗？
- 测试是否验证错误已修复？
- 边缘情况是否已覆盖？

**6. 相关代码：**
- 其他地方是否具有相同模式可能存在相同错误？
- 是否也应该修复其他类似代码？

## 要检查的内容

✅ **根本原因分析**
- 修复是否解决了根本原因或只是症状？
- PR/提交中的说明是否清楚？

✅ **回归测试**
- 是否有一个没有此修复就会失败的新测试？
- 测试是否涵盖报告的错误场景？
- 相关边缘情况是否已测试？

✅ **副作用**
- 这是否会破坏现有功能？
- 是否需要检查类似的代码路径？
- 这是否以意外的方式改变行为？

✅ **修复范围**
- 修复是否适当范围（不过宽，不过窄）？
- 是否修复了所有错误实例？
- 调查期间是否发现了相关错误？

## 要跳过的内容

❌ **完整架构审查** - 除非修复揭示架构问题
❌ **全面测试审查** - 专注于回归测试，而不是整个测试套件
❌ **主要重构建议** - 除非直接与防止类似错误相关

## 警告标志

🚩 **没有错误测试** - 我们如何防止回归？
🚩 **修复不匹配根本原因** - 这是在修复症状吗？
🚩 **超出错误的广泛更改** - 是否应拆分为单独的 PR？
🚩 **其他地方的相似模式** - 那些也应该修复吗？

## 要问的关键问题

使用 `reference/review-psychology.md` 进行措辞：

- "我们能否添加一个没有此修复就会失败的测试？"
- "我在[其他文件]中看到这个模式 - 是否有相同问题？"
- "这是否修复了根本原因或掩盖了症状？"
- "此更改是否可能影响[相关功能]？"

使用 `reference/priority-framework.md` 将发现分类为关键/重要/建议/可选。

**内联评论示例：**

```
**data/auth/BiometricRepository.kt:120** - 建议：提取空处理

<details>
<summary>详细信息</summary>

根本原因分析：BiometricPrompt 结果是可空的，但代码假定非空，在取消时导致崩溃（PM-12345）。

考虑提取空处理模式：

\\```kotlin
private fun handleBiometricResult(result: BiometricPrompt.AuthenticationResult?): AuthResult {
    return result?.let { AuthResult.Success(it) } ?: AuthResult.Cancelled
}
\\```

如果添加其他生物识别认证点，此模式可以重用。
</details>
```

```
**app/auth/BiometricViewModel.kt:89** - 建议：添加回归测试

<details>
<summary>详细信息</summary>

添加取消场景的测试以防止回归：

\\```kotlin
@Test
fun `when biometric cancelled then returns cancelled state`() = runTest {
    coEvery { repository.authenticate() } returns Result.failure(CancelledException())
    viewModel.onBiometricAuth()
    assertEquals(AuthState.Cancelled, viewModel.state.value)
}
\\```

这可以防止刚修复的错误回归。
</details>
```
