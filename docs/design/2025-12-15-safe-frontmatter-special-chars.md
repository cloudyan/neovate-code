# 安全 Frontmatter 特殊字符处理

**日期:** 2025-12-15

## 背景

`safeFrontMatter` 实用程序无法解析在值中包含特殊 YAML 字符的 frontmatter。例如，包含 `allowed-tools: Read(**), Exec(git log), Write()` 的命令文件会抛出"Failed to parse frontmatter"错误。

当前修复仅处理值中包含冒号的简单情况，但对包含括号、星号、方括号和其他特殊字符的复杂模式失败。

## 讨论

**考虑的方案:**

1. **改进自动修复正则表达式** - 增强当前模式以检测和引用包含特殊 YAML 字符的任何值
2. **引用所有非简单值** - 自动引用任何不是简单字符串/数字/布尔值的值（已选择）
3. **提供更好的错误指导** - 保持解析严格但给用户提供清晰的错误消息

**决定:** 选择选项 2，因为它更健壮且使用更简单的逻辑捕获所有边界情况。

**注释处理:** Frontmatter 中的注释（以 `#` 开头的行）应按原样保留。仅处理键值行。

## 方法

使用反向逻辑：不是检测有问题的字符，而是定义"简单"值的样子并引用其他所有内容。

- 简单值: 匹配 `/^[a-zA-Z0-9_.\\-\\s]+$/` 的纯字符串、数字、布尔值
- 如果值不匹配简单模式且尚未引用，则将其包装在双引号中

## 架构

### 正则表达式模式

1. **匹配键值行**: `/^(\\s*[a-zA-Z0-9_-]+\\s*:\\s+)(.+)$/gm`
2. **简单值模式**: `/^[a-zA-Z0-9_.\\-\\s]+$/`
3. **跳过条件**:
   - 行是注释（以 `#` 开头）
   - 值已经引用（`\"...\"` 或 `'...'`）
   - 值匹配简单模式

### 代码流程

```
对于 frontmatter 中的每行:
  如果行是注释 → 跳过
  如果行是键值:
    如果值已经引用 → 跳过
    如果值匹配简单模式 → 跳过
    否则 → 将值包装在引号中，转义内部引号
```

### 边界情况

- 多行值（以空白开头的行）→ 跳过，不是键值
- 空值（`key:`）→ 跳过，已有效
- 包含内部引号的值 → 使用 `\\\"` 转义

### 要修改的文件

1. `src/utils/safeFrontMatter.ts` - 更新正则表达式逻辑
2. `src/utils/safeFrontMatter.test.ts` - 为特殊字符添加测试用例

注意: `src/outputStyle.ts` 不需要更改，因为它已经使用 `safeFrontMatter`。

### 测试用例

1. `allowed-tools: Read(**), Exec(git log), Write()` → 自动引用
2. `argument-hint: [--branch <branch>]` → 自动引用（方括号）
3. 保留注释的混合 frontmatter
4. 已经引用的值保持不变
