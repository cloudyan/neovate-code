# 使用渐进式披露改进 /init 命令

**日期：** 2025-12-02

## 背景

当前的 `/init` 命令通过分析代码库并将所有信息放入单个文件来自动生成全面的 `AGENTS.md` 文件。然而，关于LLM上下文管理的研究（来自 HumanLayer 文章 "Writing a Good CLAUDE.md"）揭示了这种方法的几个问题：

1. **LLMs是无状态的** - 它们只知道上下文窗口中的内容，使 AGENTS.md 变得至关重要
2. **指令过载** - LLMs 可以可靠地遵循约150-200条指令；Claude Code 的系统提示已经使用了约50条
3. **少即是多** - AGENTS.md 中非普遍适用的内容越多，LLMs 越可能忽略它
4. **长度很重要** - 最佳实践是根 AGENTS.md 文件少于60行
5. **自动生成有问题** - AGENTS.md 是框架中最高杠杆点；它值得仔细手动制作

该文章主张：
- 最小化、普遍适用的 AGENTS.md（仅 WHY/WHAT/HOW）
- **渐进式披露** - 指向代理仅在需要时阅读的单独文档文件
- 永远不要将 AGENTS.md 用作 Linter 替代品或命令倾倒地
- 完全避免自动生成

然而，完全移除 `/init` 将使用户没有指导。目标是改进 `/init` 以遵循渐进式披露原则，同时仍提供有用的脚手架。

## 讨论

### 关键设计决策

**问题1：哪些改进方面最重要？**
- **渐进式披露（A）** - 创建最小的 AGENTS.md，引用单独的文档文件
- **减少指令（B）** - 目标少于60行，专注于普遍适用的 WHY/WHAT/HOW
- **决策：** A和B一起 - 它们自然互补

**问题2：如何处理文档文件结构？**
- 选项A：仅引用现有文档
- 选项B：创建 AGENTS.md 和单独的文档文件
- 选项C：建议额外文档但不创建它们
- **决策：** 选项B - 分析代码库并创建所需的文档结构

**问题3：使用什么架构方法？**
- 选项1：使用模板的单次生成（简单但不灵活）
- 选项2：两阶段分析（自适应，只创建需要的内容）
- 选项3：结合结构化输出和程序化限制的混合方法
- **决策：** 选项2 - 两阶段提供智能以避免不必要的文件

### 权衡

**两阶段方法的优点：**
- 仅创建实际需要的文档
- 更好地遵循"少即是多"原则
- 智能处理不同类型的项目

**两阶段方法的缺点：**
- 需要两次 LLM 调用（更慢，更昂贵）
- 更复杂的实现
- 误判需要内容的风险（通过保守创建缓解）

## 方法

将 `/init` 转换为智能两阶段文档生成器，使用渐进式披露原则创建最小 AGENTS.md + 目标文档文件。

**核心原则：**
1. AGENTS.md 保持最小（<60行），只有 WHY/WHAT/HOW
2. 所有详细信息进入单独的 `docs/agent/*.md` 文件
3. 仅在存在实质内容时创建文档文件
4. AGENTS.md 包含"渐进式披露"部分，列出可用文档
5. 提醒用户在生成后手动审查和精炼

## 架构

### 第一阶段：发现与规划

**分析的输入：**
1. `package.json` / `Cargo.toml` / 构建配置 → 命令，技术栈
2. 现有 `AGENTS.md` / `CLAUDE.md` / `.cursorrules` → 保留有价值的内容
3. `README.md` → 项目目的，设置说明
4. `docs/` 目录 → 检查现有文档
5. 关键源文件 → 架构模式（非详尽）

**结构化输出（JSON）：**
```typescript
{
  agentsContent: {
    why: string,      // <100字
    what: string,     // <150字
    how: string       // <100字，最多3-5个命令
  },
  docsToCreate: [
    {
      path: "docs/agent/development_commands.md",
      purpose: "所有构建、测试、lint命令",
      content: string
    },
    // 仅包含实质内容的文件
  ]
}
```

**在提示中强制执行的大小限制：**
- WHY: 最多100字（1-3句）
- WHAT: 最多150字（要点）
- HOW: 最多100字（3-5个关键命令）
- 目标：AGENTS.md 总计40-60行

### 第二阶段：生成

**AGENTS.md 结构：**
```markdown
# AGENTS.md

关于在此存储库中工作的 CODE AGENT 的指导。

## WHY: 目的和目标
[1-3句，<100字]

## WHAT: 技术栈
[要点，<150字]

## HOW: 核心开发工作流
[3-5个关键命令，<100字]

## 渐进式披露

如需详细信息，请根据需要查阅这些文档：

- `docs/agent/development_commands.md` - 所有构建、测试、lint、发布命令
- `docs/agent/architecture.md` - 模块结构和架构模式
- `docs/agent/testing.md` - 测试设置、框架和约定

**在执行任务时，首先确定哪些文档是相关的，然后只阅读那些文件。**
```

**文档文件结构：**
```
docs/agent/
  ├── development_commands.md   （如发现命令）
  ├── architecture.md            （如发现模式）
  ├── testing.md                 （如发现测试设置）
  └── conventions.md             （如发现强模式）
```

**内容分配：**
- AGENTS.md: 仅普遍适用的高级信息
- 命令文档: 所有构建/测试/lint/开发/发布命令
- 架构文档: 模块结构、模式、数据流、插件系统
- 测试文档: 测试命令、框架、文件位置、约定
- 约定文档: 仅在存在强模式时（导入、命名、组织）

### 错误处理

**现有 AGENTS.md：**
- 与生成版本进行比较
- 显示差异并提示："AGENTS.md 存在。替换？[y/n]"
- 保留自定义用户内容

**现有 docs/agent/ 文件：**
- 检查冲突
- 询问每个文件："替换 docs/agent/[filename]？[y/n]"
- 允许选择性替换

**缺少信息：**
- 如果类别信息不足，则不创建该文档
- AGENTS.md 始终创建最小值：WHY, WHAT, HOW
- 非常简单的项目可能不需要额外文档

**验证：**
- 验证生成后 AGENTS.md 少于60行
- 如果超过：自动将内容移至相应文档文件
- 硬限制的程序保护

**用户反馈：**
- 摘要："创建了 AGENTS.md（45行）+ 3个文档文件"
- 列出创建的文件及用途
- 提示："手动审查和精炼以获得最佳结果"

### 实现

**命令结构：**
```typescript

const discoveryPrompt = {

  {
    agentsContent: { why, what, how },
    docsToCreate: [{ path, purpose, content }]
  }
  限制：why <100w, what <150w, how <100w, 3-5个命令`
};

// 第二阶段：解析 JSON，创建文件
// 为每个文件使用写入工具
// 验证行数
```

**关键依赖：**
- 重用现有工具：read, write, ls, grep
- AI SDK 结构化输出或 JSON 模式用于第一阶段
- 无新外部依赖

**文件操作：**
1. 如缺失则创建 `docs/agent/` 目录
2. 写入 AGENTS.md（始终）
3. 根据第一阶段计划写入文档文件
4. 显示创建摘要

**测试：**
- 单元测试：JSON 解析，行数计算，路径生成
- 集成测试：模拟 LLM，验证正确文件创建
- 手动测试：在多样化项目上运行（单体仓库，简单应用，库）
