# Translate Documents

## Instructions

此技能用于将英文文档翻译为中文，支持多种文档格式包括skill文件、prompt文件、markdown文件等。翻译时会保持原有的文档结构和格式。

<thinking>
在开始翻译任务之前，我需要考虑：
1. 源文档的语言（英文）
2. 目标语言（中文）
3. 文档格式类型（skill、prompt、md等）
4. 如何保持原文档格式和结构
5. 是否需要保留代码块、frontmatter等特殊内容
</thinking>

### 步骤1：分析源文档

<thinking>
分析文档结构：
1. 确认文档类型（skill、prompt、md等）
2. 识别 frontmatter 部分
3. 识别代码块、列表、标题等结构
4. 确定哪些部分需要翻译，哪些保持不变
</thinking>

1. 识别文档类型和特殊结构
2. 识别 frontmatter（如果存在）
3. 识别代码块（```code```）、行内代码（`code`）、引用块等
4. 识别表格、列表等特殊格式

### 步骤2：翻译策略

<thinking>
翻译策略需要考虑：
1. 标题和正文用中文翻译
2. 代码块保持原文不变
3. 文件路径、URL、代码中的变量名等保持原文
4. frontmatter中的text内容翻译但结构保持
</thinking>

1. **标题翻译**：将所有级别标题翻译为中文
2. **正文翻译**：将段落、描述性文本翻译为中文
3. **保持原文内容**：
   - 代码块（```内的内容）
   - 代码引用（`内的内容）
   - 文件路径
   - URL链接
   - 代码中的变量名、函数名
   - 配置项名称
4. **Frontmatter翻译**：保持yaml结构，翻译文本内容
5. **列表和表格**：翻译文本内容，保持格式结构

### 步骤3：执行翻译

<thinking>
执行翻译时需要：
1. 逐段处理文档内容
2. 识别并保留特殊标记
3. 对文本内容进行准确翻译
4. 保持格式一致性
</thinking>

1. 逐段处理文档内容
2. 保留原文档的格式结构
3. 准确翻译文本内容
4. 验证翻译后文档的完整性

### 步骤4：验证结果

<thinking>
验证翻译结果：
1. 检查格式是否完整保持
2. 确认代码块未被翻译
3. 验证链接和路径是否有效
4. 确保翻译内容准确
</thinking>

1. 检查文档结构是否完整
2. 确认代码块、配置项等未被误翻译
3. 验证文档可读性和准确性
4. 确保翻译后的文档功能完整

## 注意事项

- 保持原文档的格式和结构完整性
- 不翻译代码、配置文件内容、文件路径、URL
- 翻译前确认文档内容是否包含敏感信息
- 在翻译后检查文档的可用性和准确性
- 特别注意技能文件中的结构化数据格式，确保翻译不破坏功能
